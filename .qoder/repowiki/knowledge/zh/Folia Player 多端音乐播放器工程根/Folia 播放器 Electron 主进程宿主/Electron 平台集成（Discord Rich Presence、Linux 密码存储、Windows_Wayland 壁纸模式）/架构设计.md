模块由四个相互独立的 CJS 文件组成，每个文件封装一个平台/功能域的能力，并通过工厂函数 + 依赖注入的方式暴露可测试的 API：
- `discordPresence.cjs`：通过 `createDiscordPresenceController` 创建控制器，内部维护 `@xhayper/discord-rpc` 客户端生命周期，使用 `publishStatus` 发布 enabled/configured/connected/error/applicationId 等状态；`buildDiscordActivity` 将播放快照转换为 Discord Activity，并以 `DISCORD_PRESENCE_UPDATE_INTERVAL_MS` 节流。
- `linuxPasswordStore.cjs`：纯函数 `resolveLinuxPasswordStore` 根据 `platform`、`argv`、`env.FOLIA_PASSWORD_STORE`、`XDG_CURRENT_DESKTOP` 决定是否追加 `--password-store=gnome-libsecret`，KDE 会话保持 Chromium 默认检测。
- `wallpaperWatchdog.cjs`：针对 Wayland/X11 的“包装进程”模型（windowtolayer → Folia），提供 `recoverToNormalWindow`、`startParentLivenessProbe`、`handleWindowBuildFailure`、`handleRendererGone` 等入口，并通过持久化的 `WALLPAPER_WRAPPED_CRASH_COUNT_KEY` 实现崩溃循环保护。
- `windowsWallpaperController.cjs`：针对 Windows 的 `folia-wallpaper-helper.exe` 子进程管理，通过 JSONL stdout 事件流解析（`parseHelperEventLine`），维护 attached/attaching/degraded 状态机、心跳超时、健康计时器与崩溃阈值（`CRASH_LOOP_THRESHOLD`），所有副作用（spawn/timers/store）通过 options 注入以便无头单元测试。
依赖方向单向：各模块仅依赖 Node.js 内置模块（child_process、process、fs via store）和第三方库（`@xhayper/discord-rpc`），不互相引用，由上层 main 进程组合调用。
