- 单元测试文件以 `<target>.test.ts` 命名并按业务域子目录组织，通过 `describe`/`it`/`expect` 配合 `vi.fn()`、`vi.spyOn`、`vi.useFakeTimers` 构造可预测的执行环境。
- 对浏览器/平台 API（Web Audio、MediaElement、Electron 等）采用集中式 fake 工厂（如 `fakeAudioGraph.ts` 中的 `createFakeGainNode`、`createFakeChain`）替代真实实现，使断言聚焦于调度形状而非渲染结果。
- UI 测试通过 `page.addInitScript` 在浏览器启动前注入全局 Mock 数据与配置，避免在测试步骤中逐条设置状态，并将固定数据（Netease、Navidrome、本地库）以内联 fixture 形式声明。
- 版本相关常量（如 `APP_VERSION`、`GUIDE_VERSION_STORAGE_KEY`）从 `package.json` 读取而非硬编码，防止发版后 UI 引导弹窗逻辑导致截图回归失败。
- 截图回归测试将期望图像保存在 `*.spec.ts-snapshots/` 目录下，新用例首次运行通过后需提交快照作为基线。
- 手工脚本按用途分目录存放（`manual/bili-livesong`、`manual/lyric-audit`、`manual/stage-client`），每个子目录自包含 README、主入口与 fixtures，便于独立运行与调试。
