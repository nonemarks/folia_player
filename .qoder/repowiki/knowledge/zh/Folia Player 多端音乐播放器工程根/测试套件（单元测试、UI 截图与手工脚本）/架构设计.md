测试代码按运行环境与用途划分为三个并列目录：
- `test/unit/`：基于 Vitest 的纯函数/服务层单元测试，按业务域（automix、lyrics、onlineMusic、services、visualizer 等）镜像源码目录结构组织，每个被测模块对应一个或多个 `.test.ts` 文件；通过 `@/` 路径别名直接导入被测试源码。
- `test/ui/`：基于 Playwright 的端到端 UI 测试，使用 `.spec.ts` 命名约定，借助 `helpers/appState.ts` 注入应用初始状态（如 `APP_VERSION`、`GUIDE_VERSION_STORAGE_KEY`），并通过 `page.addInitScript` 在浏览器上下文内挂载 Mock 数据（Netease、Navidrome、本地库等），截图断言产物保存在 `app.screenshot.spec.ts-snapshots/` 下。
- `test/manual/`：不纳入自动测试流程的手动脚本，包含 CLI 探针（`netease_lyrics_cli.ts`、`kugou_test.ts`）、内存/性能探测（`visualizer-memory-probe.mjs`、`analysis_idle_release.mts`）、交互式演示（`stage-client/`、`lyric-audit/`）以及平台特定脚本（`watch-smtc.ps1`、`.cjs/.mts/.mjs` 混合）。依赖方向单向指向被测试源码，测试内部通过自定义 fake/mocks（如 `automix/fakeAudioGraph.ts` 模拟 Web Audio API）隔离外部系统。
